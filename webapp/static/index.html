What is the rotation service used for?

Rotation is a separate trusted client process, not part of the gRPC server. It creates the initial encrypted demo records and replaces a record’s encryption after an identity is revoked.

  1. 1
    Revoke access

    The server disables the identity and queues every affected customer record.

  2. 2
    Decrypt locally

    Rotation uses its own recipient envelope to decrypt the latest version inside the rotation process.

  3. 3
    Generate fresh encryption

    It creates a new random DEK, ciphertext, and envelopes for the remaining active recipients.

  4. 4
    Upload the next version

    The server validates the version and recipient set, then stores only the new encrypted object.

What rotates: the object DEK, ciphertext, nonce, and recipient envelopes. The long-lived server and client scalar shares do not rotate in this workflow.

Why it is trusted: the rotation process temporarily sees plaintext and the DEK. Selecting rotation in this browser only demonstrates its read/decrypt capability; actual jobs run with make rotate.
